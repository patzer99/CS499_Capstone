CS 499 Computer Science Capstone

My Journey Through Computer Science

One of the biggest things I've taken away from my time in the Computer Science program at Southern New Hampshire University is that I've learned to look at software development from a much broader perspective. Earlier in my education, I was mostly focused on getting my code to work and making sure the program did what it was supposed to do. While that is still important, I've learned that there is much more to developing good software than simply getting the right output.

Today, I find myself thinking more about the people who will actually use the application and what it will take to maintain or improve that application over time. I consider things like usability, reliability, security, and how changes to one part of a program might affect another. That change in my thinking has probably been one of the most valuable parts of my education because it has helped me approach programming as more than just writing instructions for a computer.

Although most of my coursework at SNHU was completed independently, I've come to understand how important communication and feedback are in software development. One example comes from a Tekken training application I've been developing outside of my coursework.

When I started working on the application, I approached it mainly from my own perspective as the developer. However, feedback encouraged me to think more about how different people would interact with it. Someone with a strong programming background might understand how an application works, but that doesn't necessarily mean the average user will find it easy to navigate.

That experience changed how I approached the project. Instead of expecting users to figure out how the application works, I began thinking about how to make the application work better for them. I'm still developing and improving it, but I've become much more conscious of usability, accessibility, and designing with the user in mind.

For me, this reinforced something I've learned throughout my education: being a good developer isn't just about knowing how to write code. It's also about being able to listen, consider different perspectives, and make decisions that improve the experience for the people using the software.

Of all the technical areas I've studied throughout the Computer Science program, I feel that I've grown the most in software engineering. Earlier in my education, I was primarily concerned with understanding the code and getting the application to work. Over time, I've developed a better understanding of the planning, organization, testing, and maintenance that go into building software.

One thing I've learned is that making a program work is only part of the job. I now think more about how the different parts of an application work together, what could go wrong when changes are made, and how the application might need to evolve over time.

My CS 499 capstone gave me an opportunity to put that thinking into practice. I returned to an inventory application I originally developed in CS 360 and began identifying areas that needed improvement. Instead of starting over, I worked with the existing code, added missing functionality, improved input validation, and tested the application to make sure my changes didn't interfere with features that were already working.

That experience helped me appreciate the importance of maintaining and improving existing software. I realize that software development isn't always about creating something new. Sometimes it's about understanding what someone has already built and figuring out how to make it better.

Security is another area where my perspective has changed throughout my education. Before studying computer science, I understood that cybersecurity was important, especially with how often we hear about companies experiencing data breaches and having their customers' information stolen. However, I hadn't given much thought to what that meant from the perspective of someone actually developing software.

As I've learned more about programming, I've started to understand that security needs to be considered during development rather than treated as something to address afterward. My CS 499 capstone helped reinforce that lesson when I revisited the login system in my original inventory application. The application had been storing passwords in plain text, which created an unnecessary security risk. As part of my database enhancement, I changed how passwords were stored by implementing password hashing.

While I still have plenty to learn about software security, this experience helped me understand how decisions made during development can affect the people using an application. It also reinforced the importance of thinking beyond whether a feature works and considering whether it works safely.

Algorithms and data structures are another important part of what I've learned throughout the program. When I worked on the second enhancement of my inventory application, I wanted to add searching, sorting, and filtering capabilities. These were features I was already comfortable with from using other applications, so I had a pretty good idea of how I wanted them to work.

My goal was to bring that same level of convenience into my own application. I used an ArrayList to help organize inventory items and implemented features that allowed users to search for products, sort inventory, and identify items with low quantities.

This experience gave me an opportunity to apply what I've learned about organizing and processing data while also thinking about the user experience. It reinforced the idea that algorithms and data structures aren't just concepts we study in class. They're part of what makes everyday applications useful and easier to navigate.

I also recognize that as an application grows, the way information is organized and processed becomes even more important. That's something I want to continue improving as I develop larger projects.

Working with databases has also helped me think more about how information should be managed over time. During my third capstone enhancement, I expanded the inventory application's database functionality to keep a history of inventory changes.

One of my main reasons for adding this feature was troubleshooting. If something goes wrong with an inventory record, I wanted there to be a way to look back at previous changes and better understand what happened. Without that information, investigating mistakes could become much more difficult.

This enhancement helped me appreciate that databases do more than simply store information. How that information is organized and maintained can affect how easily problems are identified and resolved. It also connects to my growing interest in building applications that are reliable and easier to maintain over time.

My career goals involve both building my own software business and establishing myself professionally in the technology industry. One of my first priorities after completing my degree is to formally establish my software business and publish at least one of the applications I've been developing. I've always been interested in creating my own products, and I want to take what I've learned throughout my education and turn those ideas into something people can actually use.

Once I've taken those initial steps, I plan to focus more heavily on getting my foot in the door professionally. I'm open to different opportunities within the technology industry because I understand that gaining experience is an important part of building a career. I want to continue developing my technical skills, learn from experienced professionals, and become more familiar with how software and technology systems are maintained in real-world environments.

Financial stability is also an important part of my plan. I have family responsibilities, and I want to establish a reliable source of income while continuing to develop my own software projects. My goal is to use the experience and financial resources I gain through professional employment to support my family and help grow my business over time.

Ultimately, I don't see working in the technology industry and running my own software business as competing goals. I see them as two parts of the same journey. My education has given me a foundation to begin pursuing both, and I know I'll continue learning as I move forward.

The three enhancements presented in this ePortfolio reflect the skills and perspectives I've developed throughout my computer science education. For software design and engineering, I improved my original CS 360 inventory application by adding the ability to edit existing inventory items and strengthening input validation. For algorithms and data structures, I implemented searching, sorting, and filtering to make inventory information easier to manage. Finally, for databases, I added inventory change history and improved password storage through hashing.

Although each enhancement focuses on a different area of computer science, they all contribute to the same goal: making the application more useful, reliable, secure, and maintainable. Together, they demonstrate how I've learned to approach software development from a broader perspective.

As I move forward, I want to continue building on these skills through my own software projects and professional experience. I know there is still plenty for me to learn, but I'm leaving this program with a better understanding of how to approach problems, evaluate solutions, and develop software with the people who will use it in mind.
